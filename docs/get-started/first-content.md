# 发布第一条内容

前面几步做完，系统就完整了。这一页走一遍四件最常用的事，每件都点出**它会不会弹、弹在哪个端**。

## 发一条通知

**通知发布** → 选班级 → 填标题和内容 → 选优先级 → 发布。

| 优先级 | 学生端表现                                                                 |
| ------ | -------------------------------------------------------------------------- |
| 普通   | 课间弹胶囊，点击展开；**上课时段只进队列**，下课自动补弹                   |
| 重要   | 同上，卡片上带优先级标签                                                   |
| 紧急   | **无论是否上课都立即展开**（卡片内部红色呼吸光晕 + 紧急角标），45 秒后收起 |

**上课时段发紧急通知会被拦一次。** 服务端返回 `409 URGENT_DURING_CLASS`，前端弹一个全屏二次确认，
上面写着"现在为上课时间段……"、正在上的那节课，还有待发布的标题；确认按钮带 **3 秒倒计时**，
倒计时结束前点不动。确认之后才真的发出去。

这个拦截是**服务端做的**，绕过界面直接调接口一样会被拦 —— 它是产品行为，不是前端提醒。

## 布置一份作业

**作业发布** → 选班级 / 科目 → 填标题与要求 → 选**所属日期** → 发布。

> 作业按**所属日期**归类，不是按录入时间。晚上 8 点留的作业算今天。
> 老师可以给今天、明天甚至上周补录一份作业，客户端按日期查得到。

附件支持站内相对路径或 `http(s)://` 链接（其他 scheme 服务端会拒，避免被当成脚本执行）。

学生端那边默认是**看板模式**：按科目分卡片、每条作业完整显示要求、整个看板缩放到刚好铺满屏幕；
老师也可以在教室机器上直接**录入作业**、勾选**未交名单**（教室机器用的是班级账号）。

## 叫一位同学

**通知发布 → 叫人**（或管理员在**学生管理 → 叫人**）→ 选学生 → 点一个快捷短语或自己写一句 → 发送。

| 级别     | 学生端                                                             |
| -------- | ------------------------------------------------------------------ |
| 普通叫人 | 课间显示「叫人」胶囊，点击展开；**上课时段只进队列**，下课自动弹出 |
| 紧急叫人 | **无视上课时段立即展开**，上课时被收起后仍保留胶囊、可再次点开     |

文案是「请 XXX 同学找 XXX 老师」，卡片上是「收到」按钮（复用通知的已读机制）。

> 学生管理页是管理员专属，但班主任与科任老师同样需要叫人，所以给老师留的入口在「通知发布 → 叫人」。

## 录一次成绩

**成绩录入** → 选班级与考试名称 → 单条录入 / 批量录入 / 导入表格。

- **科目**下拉同样是全校统一目录，选一个该班还没有的科目会自动建课。
- 导入表格支持 `.xlsx / .xls / .csv / .tsv`，列名按同义词自动映射（「学号→学生用户名」「得分→分数」），
  也可以手动改。**文件上限 8MB**，超了会返回明确的 413 而不是一句英文的内部错误。
- 导入结果会给逐行的错误与警告，`errors[].row` 是 **Excel 视角的行号**（含表头），改完可以再导。

学生端看到的是**全班总览**：表格（分数 / 得分率 / 等级）+ 柱状图 + 等级分布 + 最近更新。

## 在教室大屏上播一条提醒（需要 ClassIsland）

**ClassIsland 联动 → 下发提醒** → 选班级、填标题内容、设置显示时长与语音朗读 → 下发。

它会**落库**再推给教室。教室机器断网也不丢：插件重连后会拉取还没确认的那条，
立刻弹出来，弹完回执，不会重复弹。

如果教室客户端把「通知显示位置」设成了"只在 ClassHelper 客户端显示"，这一步会回一句
「该班教室已设置为只在 ClassHelper 客户端显示」—— 那是设计行为，不是报错。
