# 应用帮助

这一章按功能讲，重点是**行为上的约定**——什么时段会弹、谁看得见、什么情况下不动。
很多"看起来像故障"的现象其实是设计行为，下面每一页都会点出来。

| 页面                              | 讲什么                                                     |
| --------------------------------- | ---------------------------------------------------------- |
| [课表](schedules.md)              | 周视图与「今天」时间轴、单双周、学期周数、课表来源         |
| [课件](courseware.md)             | 上传、班级可见范围、推送与逐设备接收                       |
| [作业](homeworks.md)              | 按所属日期归类、看板与全屏看板、教室机器录入、未交名单     |
| [通知与提醒](notifications.md)    | 四档优先级与两种岛模式、上课时段策略、二次确认、已读与红点 |
| [叫人](calls.md)                  | 普通叫人与紧急叫人的差别、快捷短语、谁能叫谁               |
| [成绩](grades.md)                 | 录入方式、导入、等级分布、学生看到的是什么                 |

## 贯穿所有功能的三条规则

**一、权限与范围共同决定可见内容。** 同一个页面，管理员、班主任、科任老师看到的数据与能点的按钮都不一样。
前端会按权限隐藏入口，但**真正拦人的是服务端**——直接调接口一样会被拒。完整矩阵在
[角色与权限](../dev/permissions.md)。

**二、课堂提醒遵循本机布局规则。** 经典模式普通通知暂存到下课，普通叫人保留可点胶囊；
紧急通知与紧急叫人立即展开；自定义常驻模式先显示铃铛，由用户主动查看。
细节见[通知与提醒](notifications.md)。

**三、实时广播配合恢复读取。** 老师发布后服务端按班级等房间广播，客户端刷新；断线恢复重新拉取。
设备心跳和课件补领另有轮询机制，普通通知课堂暂存由客户端处理。

## 两端的差异

同一件事在 Web 管理端和桌面客户端上不一定完全一样，这是有意的：

| 事情       | Web 管理端（老师）              | 桌面客户端（教室机器）                                    |
| ---------- | ------------------------------- | --------------------------------------------------------- |
| 作业       | 发布 / 编辑 / 删除 / 看未交名单 | 看作业 + **录入作业** + 勾未交名单，不显示"完成 / 待完成" |
| 成绩       | 录入 / 导入 / 改 / 删，带统计   | 按班级开关看个人数据或集体分析                            |
| 课表       | 排课、导入、改                  | 只看（周视图 + 今天时间轴）                               |
| 通知       | 发布 / 删除 / 看已读            | 看、标为已读                                              |
| 班级与人员 | 管理员可管                      | 只能看本班                                                |

> 客户端没有"修改密码"入口，是**刻意移除的**：防止教室机器上误改班级密码后，
> 别的教室机器被锁在门外。班级密码由管理员在 Web 端维护。
